# Проверка откликов

1. Для полного импорта загрузи `scripts/hr_context.py monitor`, при необходимости --full. Для адаптивной проверки начни с `hr_context.py bot-monitor` и `docs/monitor-errors.md`: реальный безопасный интервал до браузера и retry_guard. HH сразу https://hh.ru/chat, CUA timeout_ms=60000; не начинай с главной или списка откликов. Реальные разрешения пользователя обязательны; JSON не является обходом ограничений среды.
2. Для каждого источника проверь авторизацию и пробное чтение. Не вводи пароли, не обходи CAPTCHA/MFA. При проблеме сообщи ссылку и действие один раз, продолжай другие разрешённые источники.
3. Читай с последнего успешного скана, первый импорт за согласованный период. Сверь несколько записей с интерфейсом, даты не угадывай.
4. Через `hr_store.py` добавь наблюдённые отклики и события. Указывай устойчивый `source_event_key` с площадкой; при отсутствии идентификатора составь его из ссылки, типа и известной даты события. Не используй новое текущее время на каждом скане как ключ одного старого события.
5. Отказы без доказанного автоматического происхождения: `unknown`. Шаблонные автоотказы сохраняй без полного текста и показывай общим числом. Содержательные сообщения показывай с требуемым действием, готовь черновики.
6. Запиши результат через `record-adapter-scan` с `scan_succeeded`. Ошибка не продвигает курсор. Контрольные фоновые запуски помечай `scheduled_run: true`; не дублируй один день.
7. Мониторинг сам не разрешает исходящие. Только новый подтверждённый вопрос бот-скрининга подключает docs/bot-dialog.md при согласии bot_reply и маршрут bot_responder. Пустому просмотру сабагенты не нужны. При ошибке назначь паузу через guard и реальный планировщик, не двигай checkpoint непрочитанного. Одна ограниченная диагностика Sol high на эпизод по docs/monitor-errors.md; сброс CUA не доказывает зависание сайта. Расписание: automations/bot-monitor.md. Нестандартную проблему ищи в локальном индексе, затем сохрани проверенное решение без секретов.
