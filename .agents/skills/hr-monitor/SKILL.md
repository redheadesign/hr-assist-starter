# Проверка откликов

1. Загрузи `scripts/hr_context.py monitor`, прочитай соответствующий раздел `docs/operations.md`. Реальные разрешения пользователя обязательны; JSON не является обходом ограничений среды.
2. Для каждого источника проверь авторизацию и пробное чтение. Не вводи пароли, не обходи CAPTCHA/MFA. При проблеме сообщи ссылку и действие один раз, продолжай другие разрешённые источники.
3. Читай с последнего успешного скана, первый импорт за согласованный период. Сверь несколько записей с интерфейсом, даты не угадывай.
4. Через `hr_store.py` добавь наблюдённые отклики и события. Указывай устойчивый `source_event_key` с площадкой; при отсутствии идентификатора составь его из ссылки, типа и известной даты события. Не используй новое текущее время на каждом скане как ключ одного старого события.
5. Отказы без доказанного автоматического происхождения: `unknown`. Шаблонные автоотказы сохраняй без полного текста и показывай общим числом. Содержательные сообщения показывай с требуемым действием, готовь черновики.
6. Запиши результат через `record-adapter-scan` с `scan_succeeded`. Ошибка не продвигает курсор. Контрольные фоновые запуски помечай `scheduled_run: true`; не дублируй один день.
7. Не отправляй ответы, отклики и приглашения на встречу. Нестандартную проблему ищи в локальном индексе случаев, затем запиши проверенное решение без секретов.
