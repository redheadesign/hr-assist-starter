# Инструкция агенту, который впервые открыл проект

Это рабочие механизмы HR-ассистента и пустая конфигурация. Готового профиля, входов на сайты, согласий и включённых расписаний здесь нет. Настраивай всё под человека, который сейчас обратился к тебе. Не наследуй сведения из примеров и тестов.

## Подготовка

Прочитай AGENTS.md и `.agents/skills/hr-onboarding/SKILL.md`. Найди Python 3.11+, запускай команды из корня проекта. Если Python отсутствует, помоги установить по выбору пользователя. Создай `.venv`, установи `requirements.txt`. PDF необязателен и требует `requirements-cv.txt`.

```sh
python -B -X utf8 scripts/setup.py init
python -B -X utf8 scripts/setup.py status
python -B -X utf8 -m unittest discover -s tests -v
```

`init` работает без сети. Повторный запуск добавляет отсутствующие поля новой версии, сохраняет профиль, историю и разрешения. Неизвестная версия схемы требует отдельной миграции. Windows: можно вызвать `.venv\Scripts\python.exe` напрямую без смены системной ExecutionPolicy. Обёртка `scripts/run.ps1` выбирает Python из `.venv`, затем PATH.

Codex обнаруживает навыки в `.agents/skills`; другому агенту передай AGENTS.md явно. Проверь доступность браузерного инструмента, локальных файлов и планировщика. Обычный Python не управляет сайтами самостоятельно. [Документация навыков](https://learn.chatgpt.com/docs/build-skills).

## Профиль и предпочтения

Веди диалог небольшими блоками по `docs/onboarding.md`. Используй только слова владельца и явно предоставленные материалы. Контакты и хронология: `.local/config/profile.json`; достижения: `.local/knowledge/facts.json`. Для факта, разрешённого к карьерной передаче, нужны `id`, `claim`, `source`, `confirmed: true`, `visibility: "public"`, `checked_at`. Public здесь не означает публикацию в Git.

В settings.json заполни роли, рынки, язык, часовой пояс IANA, форматы, занятость, языки и ограничения. Суммы могут оставаться неизвестными. Если ожидания известны, уточни валюту, период и net/gross. Срок выхода сохраняется в target.start_availability, тестовое до интервью в target.test_before_interview. Не предполагай ответы. Покажи профиль владельцу, после подтверждения сохрани этап review. Пропущенный этап не разрешает выдумывать сведения.

## Подключение площадок

Владелец сам входит через доступный браузер. Не собирай пароли, cookies и токены. С разрешения сделай пробное чтение кабинета. В `.local/config/adapters.json` запиши `platform`, `transport: "browser"`, `mode: "read_only"`, `read_enabled`, `initial_probe_completed`, `status`, `target_url`, `login_url`, `needs_user_action`, `control_runs_remaining: 3`.

Отдельно запиши чтение по canonical-имени площадки в permissions.read_authenticated_sources. Read-only относится к мониторингу, отправка разрешается отдельно. После разлогина обнови статус, сохрани согласие и дождись входа. CAPTCHA, MFA, предупреждения сайтов и ограничения инструментов не обходи. Первый импорт ограничь согласованным периодом; далее читай с успешного checkpoint и дедупликацией. Доступность API/OAuth проверь по актуальной документации; не переноси предположение о доступе с другого аккаунта.

## Постоянное согласие и автоответы

Предложи конкретный режим: черновики; разрешённые отклики; отклики и стандартные ответы ботам. Покажи площадки, точное резюме для каждой, передаваемые материалы, исключения и дневной предел. По явному решению владельца запиши permissions.json:

- `mode: "limited_send"`, `send_applications: true`; `automatic_uploads: true` только при разрешении загрузок.
- `standing_application_authorization`: `active`, уникальный локальный `id`, `granted_on`, `source` с смыслом поручения, `platforms`, `data`, `resume_refs` как площадка → одобренная ссылка или CV. При ограниченном сроке добавь `expires_at` с часовым поясом.
- Для бот-скрининга отдельно `reply_to_vacancy_bots: true` и `bot_dialog_authorization` с `active`, `id`, `granted_on`, `source`, `allowed_topics`. Темы выбирает владелец: опыт, портфолио, карьерные контакты, ожидания, выход, уточнение вопроса.
- Чтение кабинетов и ответы людям не выводи из согласия на отклики. Общий send_messages сам по себе не разрешает конкретную переписку.

Запиши основание в authorization_log. Упоминание поля в гайде не является согласием. Уже данное в диалоге поручение используй без повторного вопроса. JSON фиксирует решение человека и не обходит ограничения среды.

Проверь `hr_policy.py authorize --operation application --platform <ключ>` и отдельно bot_reply. Для первого запуска выбери одну вакансию, собери пакет по docs/workflow.md, проверь резюме и форму, отправь в разрешённых границах и запиши наблюдаемый статус. Неясный результат требует проверки существующей заявки до повторной попытки.

## Кампания и расписания

В settings.campaign запиши выбранные daily_minimum, daily_maximum, sources (объекты с id), parallel_agents, max_workers и catch_up_enabled. Например, цель 20 в день допустима по желанию владельца, но не обязательна. Не компенсируй недобор неподходящими вакансиями. В company-career-sources.json добавь выбранные компании: id, name, career_url, необязательный scan_group. Проверь официальный маршрут.

После поручения владельца создай штатным инструментом среды ежедневное задание по automations/daily.md, самостоятельный монитор по automations/bot-monitor.md, недельный разбор и периодический аудит резюме. Найди существующие задания перед созданием новых. Модели выбирай из доступных в среде владельца; шаблон не требует определённой подписки.

Для общей CRM выбери сохранённый локальный проект: все запуски должны видеть одну `.local`. Worktree без явной синхронизации этой базы не подходит. Сохрани реальные ID в `.local/config/bot-monitor.json` и `.local/knowledge/automations.md`. Только после создания и проверки включи enabled соответствующего режима. Проба чтения в фоне не является полным импортом; первые три полных скана контрольные.

Локальным заданиям нужны включённый компьютер, работающее приложение и доступная сессия. CLI не заменяет планировщик. Если нужный интервал или браузер в фоне недоступен, сообщи фактическое ограничение. [Документация расписаний](https://learn.chatgpt.com/docs/automations?surface=app).

## Проверка и остановка

Проверь `hr_workflow.py day`, `hr_campaign.py list`, `hr_campaign.py schedule-mode`, `hr_store.py validate`, `hr_store.py dashboard`. Панель появится в `.local/DASHBOARD.md`. До реальных отправок sent равен нулю. Клик не является отправкой, завершённая анкета не является интервью.

В `.local/knowledge/HANDOFF.md` оставь только подтверждённое состояние и оставшиеся действия. Для остановки исходящих выключи send_applications/reply_to_vacancy_bots и active у согласий; при необходимости приостанови расписания. Архивация одного чата не останавливает самостоятельные задания.

Перед обновлением сделай защищённую резервную копию `.local` вне Git, обнови код, запусти setup.py init и тесты. Для передачи другому человеку используй только Git-файлы и `privacy_guard.py --index --history`; не упаковывай рабочую папку целиком.

ZIP работает без Git. Если владелец позже хочет вести собственный репозиторий, сначала инициализируй Git в отдельной папке, проверь .gitignore и разрешённый список, добавь только общие файлы. Проверки --index/--history и build_release требуют Git. Личные данные из .local не добавляй, даже в приватный репозиторий.
