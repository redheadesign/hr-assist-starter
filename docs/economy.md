# Экономный режим агентов

`setup.py init` создаёт `.local/config/model-routing.json`. Это настройки плановых HR-задач, а не включение расписаний или согласие на отправки. Доступность моделей и браузера проверяется в среде нового владельца. Общий шаблон не меняет модель текущего ручного диалога.

| Роль | Начальная модель | При конкретной нерешённой задаче |
| --- | --- | --- |
| Координатор и тексты | Sol high | Решение владельца |
| Поиск | Luna medium | Terra medium, затем Sol high |
| Проверка компании | Terra medium | Sol high |
| Отправка, монитор, бот-ответы | Terra medium | Sol high |
| Независимое ревью | Terra high | Sol high |
| Недельный разбор | Terra high | Решение владельца |
| Аудит резюме | Sol high | Решение владельца |

В JSON находятся полные ID моделей. Astra запрещена в плановых ролях и резервных переходах. Большие доработки можно запускать вручную выбранной владельцем моделью. Если среда не предоставляет настроенную модель, выбери только доступный шаг её маршрута. Если доступного шага нет, останови эту роль и сообщи ограничение. Последовательная работа не даёт права молча перейти на модель родителя.

```sh
python scripts/hr_routing.py validate
python scripts/hr_routing.py route --role scout --available-model gpt-5.6-luna --available-model gpt-5.6-terra
```

`--available-model` повторяется для моделей, реально доступных в инструментах. Без него результат помечен availability_verified=false. Команда не определяет подписку и не создаёт агента. Перед запуском передай model и reasoning_effort явно, fork_turns=none. Для резервного шага используй --fallback-index после сверки предыдущего результата. Смена модели не отменяет блокер, ограничения или обязательный неизвестный факт.

## Короткие пакеты и ограниченные пачки

Координатор загружает нужный контекст один раз. Исследователь получает критерии и выбранные источники, автор и ревьюер получают карточку и подтверждённые факты, исполнитель получает готовый проверенный пакет и один claim. Полная история родительского диалога, архив резюме и все JSONL в пакет не входят. Текст пишет координатор, он не создаёт отдельного автора для каждого письма. Ревьюер проверяет смысл, факты и стиль владельца; формальный lint не заменяет ревью.

Параллельность включается только по решению владельца. Одновременно не более min(campaign.max_workers, worker_limits.max_active) исполнителей, вложенная делегация выключена. Один исследователь обрабатывает до четырёх сайтов, один исполнитель до четырёх последовательных откликов одной площадки. Меньшие границы берутся из worker_limits.

У каждого отклика отдельные canonical_key, ревью, claim и доказательство. Координатор выдаёт следующий claim только после сверки предыдущего результата и пересчёта остатка дневного лимита. Заранее резервировать всю пачку одному worker нельзя.

Браузер может теряться между завершёнными ходами агента. Если среда поддерживает обмен сообщениями, worker после результата сохраняет артефакт, отправляет короткое сообщение координатору и ждёт следующий пакет в том же активном ходе до 60 секунд, без final. Координатор отвечает через send_message после записи результата. Это не обычный followup_task после завершения. При четвёртом элементе, истечении ожидания, блокере или неопределённом результате worker заканчивает работу. Если такой обмен недоступен, запускай свежего worker с коротким пакетом; не предполагай сохранение вкладки.

При передаче незавершённой задачи сначала проверь существующую заявку, останови прежнего исполнителя и выполни hr_campaign handoff по docs/workflow.md. Никогда не повторяй внешнее действие вслепую. Истёкший claim требует отдельной сверки.

После 180 секунд или восьми браузерных вызовов без нового проверенного результата исследователь возвращает partial и конкретный пробел. Это предел отсутствия прогресса, не повод выдавать неполный охват за полный. Одну причину сбоя диагностируй один раз, затем передай только нерешённую часть следующей модели или зафиксируй блокер. Отсутствие вкладок само по себе не доказывает отсутствие браузерного инструмента: проверь штатное создание/выбор вкладки. При наблюдённом медленном ответе можно увеличить timeout отдельного вызова до 60 секунд вместо повторных перезапусков.

## Источники и пустые проверки

`campaign.sources` задаёт выбранные источники, `campaign.source_cadence` ограничивает дни их автоматического обхода. Ключи нормализуются по aliases площадок. Отсутствующее правило сохраняет прежний ежедневный обход выбранного источника. Владелец может назначить frequency=daily, frequency=weekly с weekdays 0..6 (понедельник..воскресенье) или frequency=manual. Например, для выбранного company_careers можно задать {"frequency":"weekly","weekdays":[0]}. Список компаний сам по себе не включает обход: company_careers должен быть выбран в sources. Не расширяй источники из-за недобора. Явный ручной поиск может иметь другую порученную область, но не переписывает расписание.

Начинай с hr_context market или monitor. Они показывают короткий day_state без подробных доказательств и статистики; --full раскрывает их при необходимости. Не вызывай hr_workflow day повторно, если свежий day_state уже получен. После новых отправок обнови состояние.

Пустой бот-монитор начинает с hr_context bot-monitor. Он читает настройки, очередь и checkpoint, не перечитывает дневную CRM, не меняет состояние и не загружает руководство ответов. Пустая очередь не отменяет разрешённую периодическую проверку входящих. Подключай docs/bot-dialog.md и отдельного исполнителя только при новом вопросе бота.

По умолчанию монитор тихий, idle_check_minutes=240. После всей пачки одна серия проверок, не таймер на каждый отклик. Учащение расписания только в согласованных границах. Для временного режима запиши локально его область, срок окончания и прежний интервал; в начале запуска после срока или завершения серии восстанови прежний интервал штатным инструментом. Запись в JSON сама не меняет планировщик и не гарантирует точное время запуска. Не оставляй частый режим бессрочно после пилота.

## Измерение и обновление

Сохраняй в `.local/reports/` и source_stats наблюдённые model, reasoning_effort, duration_seconds, agent_count, tokens, число проверенных источников, отправок, ошибок и переключений. Неизвестное равно null. При разных моделях храни отдельные записи, не приписывай весь расход последнему исполнителю.

`hr_usage.py` принимает только явно выбранные локальные журналы Codex и выводит счётчики без переписки и аргументов инструментов. Выгрузка разрешена только в `.local`. Формат журналов зависит от среды, отсутствие счётчика не означает нулевой расход. Суммарные входные токены включают повторные вызовы; cached_input_tokens входят в input_tokens, reasoning_output_tokens входят в output_tokens. Их нельзя прибавлять второй раз. Инструменты внутри одного вызова могут не отражаться в числе верхнеуровневых tool_calls. Для сравнения снимай одинаковую фазу через --through, учитывай исправления и не учитывай одну сессию дважды.

Сравнивай расход на проверенный источник или подтверждённую отправку при сопоставимом охвате и качестве. Малая модель может потратить больше из-за повторов. Разовый пилот, API-цена и общий процент лимита аккаунта не доказывают процент дневной экономии. Не запускай сравнительный тест моделей каждое утро.

OpenAI описывает выбор меньшей модели и сокращение контекста/ответа в [cost optimization](https://developers.openai.com/api/docs/guides/cost-optimization), повторное использование стабильного префикса в [prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching). API Batch/Flex не включаются этими шаблонами и не заменяют интерактивный браузер. Реальные лимиты Codex проверяй отдельно в аккаунте.

После обновления запусти setup.py init и hr_routing.py validate. Init добавляет отсутствующие поля и сохраняет настройки владельца. Затем сверяй существующие задания в приложении: модель, уровень рассуждения, промпт, проект и периодичность. Обнови их штатным инструментом в уже разрешённых границах. Изменение файлов репозитория само не обновляет старые задания, не создаёт новые согласия и не подключает браузер.
