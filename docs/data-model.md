# Локальные данные и команды

Корень данных: `.local`. Формат JSON/JSONL, UTF-8. Создание с нуля: `python scripts/setup.py init`. Версия: `.local/schema-version.json`. Рабочую базу не копируй в примеры, тесты или Git.

## Настройки и профиль

- `config/profile.json`: имя, заголовок, локация, контакты, ссылки, краткое описание, опыт, образование, навыки, языки. Пустые значения не являются подтверждёнными фактами.
- Элемент `experience`: `company`, `role`, `start`/`end` в формате YYYY-MM либо подтверждённая строка `period`, список `bullets`. Текущая работа может иметь `end: null`. Сроки и общую длительность проверяет агент.
- Элемент `education`: `institution`, `program`, `period`. Навыки и языки: списки строк. В публичный профиль не помещай внутренние заметки.
- `config/settings.json`: язык, часовой пояс IANA, цели, стиль, площадки и пожелания по расписанию. Зарплата по умолчанию неизвестна и не публикуется.
- `config/permissions.json`: разрешения на чтение по источникам и на отдельные внешние действия, журнал согласований. Они не обходят ограничения инструментов.
- `knowledge/facts.json`: список фактов с `claim`, `source`, `confirmed`, `checked_at`.
- `documents/manifest.json`: хэш, локальный путь, исходное имя, назначение и тип документа. `intake.py` не даёт разрешения на внешнюю загрузку.

## Операционные таблицы

- `vacancies.jsonl`: `id`, `source`, `company`, `title`, `source_url`; при необходимости `segment`, требования и дата обнаружения.
- `applications.jsonl`: `id`, `vacancy_id`, `channel`, `sent_at`, `record_origin`, подтверждение пользователя или ключ источника. Черновик не является отправкой.
- `events.jsonl`: `id`, `application_id`, `type`, `at`, `source_event_key`, ссылка на источник, `confidence`, при отказе `rejection_type`. У содержательного сообщения может быть `message_text`.
- `feedback.jsonl`: связь с откликом, причина, краткая оценка и источник. Не интерпретируй молчание как доказанный отказ по причине.
- `adapter-scans.jsonl`: успешность попытки, статус доступа, период, число просмотренных/импортированных записей. Неудачная попытка не двигает успешный курсор.
- `experiments.jsonl`: план эксперимента, варианты, гипотеза, период и критерии сравнения.
- `outreach-targets.jsonl`: цели согласованных прямых обращений и канал.
- `suppressions.jsonl`: кому нельзя отправлять повторные обращения и почему.

Последние три таблицы создаются пустыми для будущего использования; отдельной команды записи для них пока нет. До её добавления редактируй их локально последовательно, с уникальными `id`, без параллельных писателей.

## Запись через CLI

```sh
python scripts/hr_store.py add-vacancy --json .local/inputs/vacancy.json
python scripts/hr_store.py confirm-sent --json .local/inputs/sent.json
python scripts/hr_store.py observe-application --json .local/inputs/observed.json
python scripts/hr_store.py add-event --json .local/inputs/event.json
python scripts/hr_store.py add-feedback --json .local/inputs/feedback.json
python scripts/hr_store.py record-adapter-scan --json .local/inputs/scan.json
python scripts/hr_store.py summary --days 7
python scripts/hr_store.py dashboard --days 7
python scripts/hr_store.py validate
```

Перед вызовом сверяй контракт соответствующей команды в `scripts/hr_store.py` и тестах. `confirm-sent` требует `vacancy_id` и `channel`; это фиксация уже состоявшейся отправки, команда сама ничего не отправляет. `observe-application` требует `source`, `source_application_key`, `company`, `title`. Она применяется только после прямого наблюдения в разрешённом источнике.

Дедупликация: вакансия по URL, отклик по ключу источника либо паре вакансия/канал, событие по `source_event_key`. Агент обязан передать устойчивый ключ с площадкой, при отсутствии исходного идентификатора составить его из ссылки, типа и известной даты события. Без ключа команда добавляет новое событие. Реальные повторные подачи на ту же вакансию требуют отдельной проверки, не обходи защиту придуманным ключом.

Неизвестную дату отправки не заменяй датой обнаружения. Такие записи исключаются из конверсии когорты. Отчёт выбирает отклики периода и учитывает более поздние события для них; свежая когорта ещё не успела получить все ответы. Сумма недельных входящих и конверсия недельной когорты являются разными метриками.

## Реестр площадок

`config/adapters.json` содержит объект `adapters`, изначально пустой. В записи площадки: `status`, `transport`, `mode`, `target_url`, `read_enabled`, `last_auth_ok_at`, `last_successful_scan_at`, `failure_reason`, `needs_user_action`, `control_runs_remaining`.

Команда `record-adapter-scan` принимает `adapter`, `status`, `scan_succeeded`; для включения чтения нужен успешный пробный просмотр и `enable_read: true`. Это запись результата, не сетевой адаптер. Дополнительно требуется разрешение пользователя в `permissions.json`. Для первых контрольных запусков укажи `control_runs_remaining: 3`; ручной просмотр не уменьшает счётчик. Повтор одного запланированного дня не должен считаться новым контрольным запуском.

Записи выполняй последовательно. Файловая блокировка защищает отдельное добавление строки, но не является транзакцией на весь импорт и все таблицы. Одновременно запускаемые агенты должны согласовать одного писателя; для высокой параллельной нагрузки потребуется отдельное хранилище с транзакциями.

Ошибки и неизвестные статусы не исправляй догадками. Останови затронутую операцию, сохрани понятное описание локально и проверь источник.
